# 图片/视频输入适配协议（四通道）

目标：让用户"直接往对话框扔图/扔视频"就能被识别，**在任何 Agent 上都尽量可用**。

核心认知：技能无法绕过客户端输入层的拦截，但有**四条通道**可以拿到图片/视频——按顺序探测，总有一条通。遇到"识别图片/视频"请求时，不要因为客户端报"不支持图片"就放弃，先走完通道探测。

## 通道一览

### 通道 A：路径注入（客户端给路径，粘贴即用）

客户端把粘贴的图片/视频自动保存到本地，并把文件路径交给主模型（如 ZCode 桌面端会把粘贴的图片存入本地 image-cache 并给主模型路径）。

- 探测：用户消息里出现图片/视频引用，或环境里出现新的缓存文件路径
- 使用：直接 `recognize <路径>` 走委托管线

### 通道 B：附件/文件（多数客户端可用）

聊天窗口直接粘贴图片被客户端拦截（纯文本模型），但"文件/附件"发送走独立通道，主模型能拿到附件路径。

- 使用：引导用户"以附件/文件方式发送"，从附件路径读取后走委托管线
- 验证方法：让用户发一个文件附件，看主模型能否读取其路径

### 通道 C：剪贴板提取（桌面端 + 有终端/Shell，直接扔图的关键）

用户刚粘贴的图片**仍留在系统剪贴板**——即使客户端在输入层拦截了图片，剪贴板里也有一份！

- 使用：运行 `scripts/clipboard_save.py` 把剪贴板图片存为文件，再走委托管线
- 平台：Windows（PowerShell 内置，零依赖）/ macOS（需 `pngpaste`，`brew install pngpaste`）/ Linux（需 `xclip`）
- 验证：先 `python scripts/clipboard_save.py --check` 探测剪贴板是否有图片；没有则如实告知
- 注意：**视频无法从剪贴板提取**（剪贴板一般只存位图）——视频走 A/B/D 通道
- **被拒素材回收（优先于剪贴板）**：客户端拦截图片发送时，图片文件往往已被客户端保存（附件名会出现在临时/会话/下载/媒体缓存目录）——**先扫描最近修改的图片/视频文件**，取最新的使用；剪贴板作为第二选择

### 通道 D：URL 直传（全平台通用兜底）

把图片/视频传到任意可访问的 URL，把**链接**贴进对话框——链接是纯文本，任何客户端、任何纯文本模型都不会拦截。

- 使用：下载 URL → 本地文件或 Data URL → 走委托管线
- 用户侧低成本的分享方式：图床、网盘直链、临时文件托管（如 tmpfiles.org / catbox.moe / 0x0.st）等

## 处理步骤（收到"识别图片/视频"类请求时，按序执行）

1. 用户消息自带**路径** → 通道 A，直接用
2. 用户消息带 **URL** → 通道 D，下载后识别
3. 用户提到"刚粘贴了图片/发了图"但无路径：
   - **有终端的环境**：先扫描最近的图片缓存/附件目录（image-cache、临时目录、下载目录、附件目录），找到最新图片文件即使用；没有再运行 `scripts/clipboard_save.py --check`，有图 → 通道 C 提取识别
   - **无终端的环境**：引导通道 B（附件发送）或通道 D（URL 直传）
4. 以上都拿不到 → 明确告知用户当前各通道的情况与可用替代，**不假装收到图片**
5. **提取到图片/视频后一律走委托管线**（用已配置的视觉/生成模型）——**不要擅自改用本地 OCR**：OCR 只在"完全没有视觉模型且图片是纯文字截图"时作临时兜底，且需如实告知用户这是兜底方案，不是技能的正道

## 自检阶段追加项

能力自检时确认：① 当前客户端属于哪种通道（粘贴是否会产生本地路径）；② 是否有终端（决定通道 C 可用性）；③ 是否有网络下载能力（决定通道 D）。据此输出"本环境的扔图/扔视频方式指引"。

## 拦截自动检测与回收机制（主模型不变，直接发图/发视频）

用户"粘贴图片/视频直接发送"被客户端拦截（提示"模型不支持图片"）时，**主模型无需更换**，技能自动执行：

1. **检测**：用户消息提到图片/视频但素材未到达（无路径/无附件/无 URL），或用户转述客户端拦截提示 → 判定发生拦截
2. **回收**：按序寻找被拒素材——① 扫描最近修改的图片/视频文件（会话目录、临时目录、下载目录、附件目录、客户端媒体缓存），取最新的；② 剪贴板提取（仅图片，`scripts/clipboard_save.py`）；③ 用户消息中的 URL（通道 D）
3. **识别**：找到素材 → 走委托管线 → 回复用户"已自动取回你发送的图片/视频并完成识别"
4. **引导固化**：向用户说明本环境的正确发图姿势（如"粘贴图片后发送任意文字指令即可"），此后用户即可保持主模型不变、直接"扔图"

## 边界（诚实声明）

- **手机端**（如 WorkBuddy 移动版）+ 纯文本聊天模型：无终端、剪贴板不可读 → 只有通道 B（若客户端支持附件）和通道 D 可用
- **视频**：通道 C 不适用；A/B/D 均可
- 剪贴板内容可能被其他程序覆盖：提取前先 `--check`，取到即用，失败如实说
