# 图片/视频输入适配协议

场景：用户想"直接扔一张图给 AI 对话框"，让文本模型识别。**能否成功取决于客户端如何把图片交给主模型**——技能无法绕过客户端输入层的拦截，但可以探测并适配三种模式，让体验尽量接近"直接扔图"。

## 三种输入模式（先探测，再应对）

### 模式 A：路径注入（粘贴即用，最佳体验）

客户端把粘贴的图片自动保存到本地缓存，并把文件路径交给主模型（例：ZCode 桌面端会把粘贴的图片存入本地 image-cache 并让主模型拿到路径）。

- 表现：用户消息里出现图片引用或新缓存文件，主模型能读到该路径
- 应对：直接使用该路径走委托管线（`recognize <路径>`）

### 模式 B：附件/文件通道（多数客户端可用，推荐兜底）

聊天窗口直接粘贴图片被客户端拦截（纯文本模型），但"文件/附件"发送走独立通道，主模型能拿到附件路径。

- 应对：引导用户"以附件/文件方式发送图片"，从附件路径读取后走委托管线
- 验证方法：让用户发一个文件附件，看主模型是否能读取其路径

### 模式 C：完全拦截（如手机端客户端 + 纯文本聊天模型）

客户端在输入层拒绝图片，主模型根本收不到图片或路径——错误（如"当前模型暂不支持图片"）发生在**技能运行之前**。

- 应对：明确告知用户原因，引导：① 保存图片到本地并提供文件路径；② 或改用支持视觉的聊天模型；③ 或在支持附件的客户端中使用。**不假装收到图片。**

## 处理步骤（收到"识别图片/视频"类请求且用户未给路径时）

1. 先查用户消息里是否自带文件路径 → 有则直接用
2. 无路径时，在环境中查找最近的图片缓存/附件目录（如 image-cache、会话目录、下载目录、附件目录），取最新的图片文件使用——若找到，告知用户"已从 <路径> 读取"
3. 找不到 → 按模式 B 引导附件发送；附件不可用 → 按模式 C 明确说明并引导提供路径
4. 全程遵守诚实原则：看不到就是看不到，不假装

## 自检阶段追加项

能力自检时顺带确认：当前客户端属于哪种模式（粘贴图片是否会产生本地文件路径）。这决定后续所有"扔图"场景的引导话术。
