# 结果展示规范（阶段 5）与客户端内联渲染（阶段 6）

通用原则：**先花一分钟实测当前客户端支持哪种展示方式，再固化**，不要凭经验假设。

## 阶段 5：结果展示

- **统一输出目录**：当前工作区 `media_out/`。
- **图片嵌入**：优先 Markdown 相对路径语法 `![描述](media_out/xxx.png)`（若客户端可访问本地文件）；否则用可公开访问的 URL 或 Data URL，实测哪种能渲染。**绝对路径（含盘符）常被当作 URL 协议导致破图，避免使用**。
- **图片前置校验**：展示前用 PIL `Image.open(p).verify()` 校验完整性（下载中断会产坏文件）；单文件 >3MB 或宽 >2000px 先缩放成 1024 宽预览图（LANCZOS + `optimize=True`）再嵌入，同时给出原图完整路径。
- **视频嵌入**：优先 Markdown 图片语法 `![描述](media_out/xxx.mp4)`（`<video>` 原始 HTML 常被客户端过滤，先实测确认）。内联预览两个前置条件：
  ① **moov 必须前置（faststart）**——多数生成接口返回的 mp4 moov 在文件末尾，直接嵌入会卡"加载中"；
  ② **体积必须小于客户端预览上限**——**不要信猜测值，要实测**（历史：某客户端文档暗示 8MB，实际解包核实默认上限 4MB，6.6MB 的 H.264 + moov 前置视频照样卡"加载中"）。
- **转码工具**（A/C 档交付）：`libx264 + -profile:v main -pix_fmt yuv420p + -movflags +faststart`，CRF 26→30→34→38 逐档压缩，必要时降分辨率（1280→1024→854→640），直到体积 < 实测上限。
### 自动显示验证（不问用户，验证通过才算交付）

1. **嵌入前程序化检查**（全部通过才嵌入）：文件存在；图片 PIL `verify()` 且 ≤3MB、宽 ≤2000px（超限先缩放 1024 预览图）；视频 faststart 且体积 < 实测上限；Markdown 相对路径语法正确。
2. **嵌入后自动验证**：
   - 环境有截图能力（浏览器工具/系统截图）：截图聊天窗口相关区域 → 用视觉模型确认图片/视频播放器已渲染
   - 无截图能力：检查客户端是否有预览状态可查询；都没有则如实注明"已通过全部可程序化条件验证，渲染以窗口实际显示为准"，但**不主动询问用户**
3. **验证失败 → 自动修复链**（每次修复后重新验证，最多 3 轮）：
   - 图片：重新缩放/转码 → 更换嵌入方式（相对路径 → URL → Data URL）→ 检查并应用客户端渲染补丁（见阶段 6）
   - 视频：重新 faststart 转码（逐档降 CRF/分辨率）→ 更换嵌入方式 → 应用客户端渲染补丁（见阶段 6）
4. 3 轮修复仍失败：如实告知用户问题、已尝试的修复与当前可行的替代方案（附件上传 / 本地播放），不假装成功。

## 阶段 6：客户端内联渲染（仅当可访问客户端文件且默认不支持时才执行）

1. **探测**：嵌入一个 mp4 测试是否渲染成播放器；不渲染才进入修补。
2. **通用修补套路**（以 Electron 应用为例）：
   - 解包 `resources/app.asar`（`npx @electron/asar extract`）；
   - 定位 host 进程 MIME 映射表，加入视频扩展名（mp4/m4v/webm/mov/mkv/avi → video/*）；
   - 定位渲染进程处理 Markdown 本地媒体的组件（按特征函数/结构搜索，**不要硬编码文件名**，混淆名每次构建会变）；
   - 改为识别视频扩展名并渲染 `<video controls>`；
   - 重打包替换（原文件先备份为 .bak），重启验证。
   - 若代码结构变化导致无法定位，明确报错并给出手动步骤，绝不乱改文件。
3. **自愈机制**（客户端会更新/重装，补丁会丢，必须构建）：
   - 补丁前/后文件哈希快照 + 副本（存 `backups/state.json` 与 `app.asar.orig`/`app.asar.patched`）；
   - 会话启动钩子（不同平台的机制不同，先查找当前平台是否提供；没有则用定时任务/手动触发等可用方式）自动执行自检：哈希 = 补丁版 → 静默通过；= 原版（同版本补丁丢失）→ 自动恢复；哈希未知（客户端升级）→ 自动重打；失败 → 输出明确人工步骤（自检脚本退出码恒为 0，不打断会话）；
   - 文件被锁无法替换时：启动后台守护进程，等待用户关闭客户端时**静默完成替换**（原文件备份），重启即生效——全程零人工；
   - 若当前平台无钩子机制，至少交付"一键恢复脚本 + 手动步骤文档"。
4. **兜底**：一键批处理入口 + 手动步骤文档。
