# 模型来源全流程：先查后要

流程总览：**先看环境里已有什么（零成本），再看用户能给什么（补缺口）**。已有模型能覆盖的能力优先建议用户直接使用；覆盖不了的能力，才请用户提供 baseURL 与 API Key 补齐。

## 1A. 检测环境已配置的模型（优先使用，不浪费）

1. **扫描 Agent 自身配置**：查找当前环境里已有的模型配置——Agent 的 provider/模型配置、`.env`、环境变量等，列出**已有模型清单**及其凭据来源。
2. **逐模型能力探测**：
   - 识别类：用"纯色探测法"——运行 `scripts/vision_probe.py` 生成 64×64 纯色 PNG，发给模型问"这是什么颜色"，**答对才算能看图**；
   - 生成类：依据模型命名与文档判断（含 image/video/draw 等标识）；拿不准时发**最小请求**验证返回格式与产物类型；
   - 无法探测的（凭据不可读/无网络）标记"未验证"，不臆断。
3. **输出《环境已有模型能力表》**（模板见 `assets/tables.md`）供用户审阅，标注每个模型对四能力的支持：✅ 可复用 / ⛔ / 未验证。
4. **有则优先**：已有模型确认能覆盖的能力，**优先建议用户直接使用**（零新增成本、无需新密钥），经用户确认后接入；同一能力已有模型与用户候选并存时，列差异让用户选。
5. **安全同规则**：扫描与探测中读取的密钥只在本机使用，输出一律脱敏，不写入任何文档。

## 1B. 凭据补充（仅针对已有模型未覆盖的能力）

对已有模型**未能覆盖**的能力，请用户提供对应供应商的 **baseURL** 与 **API Key**（可提供多个供应商；用户也可直接指定某能力用某模型）。收到凭据后，**先向用户作出安全承诺声明（见 1C），再开始分析**。

**部分支持完全没问题**：某个供应商（或已有模型 + 新凭据的组合）可能只覆盖其中一种、两种或三种能力——支持哪些就接入哪些，不支持的如实告知即可，其余能力与流程不受阻塞。

## 1C. API Key 安全处理承诺（用户提供密钥时立即声明，逐条说明，增强安全感）

> 我会这样安全处理你的 API Key，请放心：

1. **绝不外泄**：密钥只用于调用你指定的供应商 API，不发送给任何第三方、不进任何网络请求以外的数据。
2. **只存本地凭据文件**：密钥写入本地配置文件（如 `~/.config/keys.json` 或项目 `.env`），并设置仅当前用户可读的权限（Linux/macOS 用 `chmod 600`；Windows 设用户级权限）；不写进聊天上下文、不写进任何文档。
3. **全程脱敏显示**：所有输出、日志、报错信息中，密钥一律显示为掩码（如 `sk-***abcd`），绝不回显明文；`--dry-run` 打印请求体时同样脱敏。
4. **不写入生成物**：生成的脚本、协议、README、踩坑清单、交付报告一律不含密钥；脚本统一从本地凭据文件/环境变量读取，代码中不硬编码。
5. **可随时撤销**：你可随时要求删除本地凭据文件或更换密钥；删除后对应能力自动回到"待配置"状态，不影响其他能力。

## 1D. 能力-模型自动匹配分析（针对用户新提供的凭据执行）

1. **拉取模型清单**：优先调用该供应商的模型列表接口（如 `GET {baseURL}/models`）；失败或无权限时，请用户提供模型文档或列表页。
2. **能力覆盖检查**：根据模型清单与可用端点，先确认该供应商支持哪些能力、不支持哪些能力（是否有识别/生成类模型、是否存在对应端点），逐能力标注：✅ 支持 / ⛔ 不支持。
3. **逐能力匹配**：对支持的能力，结合模型命名与能力标识（`vision`/`image`/`video`/`audio`/`multimodal` 等关键词）、上下文窗口、官方文档描述，推荐候选模型并标注**置信度**（高/中/低）与依据。
4. **无法确认时实测**：识别类用"纯色探测法"；生成类各发一次最小请求验证返回格式与产物类型。
5. **输出《能力-模型匹配表》**（模板见 `assets/tables.md`）供用户审阅。
6. **部分支持照常交付**：只支持一/两/三种能力时，支持的能力照常接入、验证、交付；不支持的能力明确标记"⛔ 供应商不支持"，不做无谓尝试（如强行调用不存在的端点），在交付报告中说明即可。
7. **用户拍板后才接入**：匹配结果必须经用户确认；用户可随时覆盖为指定模型；同一能力有多个候选时，列出差异（能力、价格、速度、质量实测对比）由用户选择，不擅自二选一。

## 铁律

- **先查后要**：环境已有模型能覆盖的能力，不得先向用户索要凭据；确无覆盖时才开始 1B 流程。
- 未确认、未验证的模型**一律不接入**；对应能力保持"待配置"状态，如实告知用户。
- **供应商不支持的能力**（模型清单/端点上不存在）：标记为"不支持"，不强行接入、不假装接入，也不阻塞其他能力。
- 接口格式不明时向用户索要文档或 curl 示例，`--dry-run` 验证后再固化，不猜格式。
- 未提供配置的能力不假装接入、不用其他模型顶替。
