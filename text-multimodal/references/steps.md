# 阶段施工细节（阶段 0~4、7）与提示词撰写规范

## 阶段 0：搭建委托通道（骨架先行，与模型解耦）

目标：一个统一脚本（A 档实际创建，可基于 `scripts/delegate_skeleton.py`；B 档内置等价函数；C 档交付源码）成为唯一委托通道。子命令契约：

- `recognize <图片路径> [识别指令]`
- `imagegen "<生成指令>" [输出路径] [--size 1K|2K|3K|4K] [--ratio 1:1|3:4|4:3|16:9|9:16|2:3|3:2|21:9] [--image 图1,图2] [--base64]`
- `videorecognize <视频路径> [识别指令] [--thinking] [--max-tokens 8000]`
- `videogen "<生成指令>" [输出路径] [--seconds 5] [--fps 24] [--size 480p|720p|1080p|WxH] [--ratio 16:9|9:16|1:1|4:3|3:4] [--negative "反向提示词"] [--seed 42] [--image 起始图] [--keyframes 图1,图2]`

通用要求：

- 每个能力一个**适配器（adapter）**，统一输入/输出契约，内部封装具体供应商的请求格式与解析；适配器分三类：OpenAI 兼容类 / 文档推导类（依据用户 curl/文档，先 dry-run 验证）/ 任务式类（提交→轮询→下载）。
- 新增或更换模型 = 新增/替换适配器 + 更新配置，**不改动主流程**。
- 本地素材自动转 Data URL（png/jpg/jpeg/webp/gif/bmp/mp4/webm/mov），http(s) 直传。
- 结果默认存当前工作区 `media_out/`（文件名带时间戳），保存后打印"绝对路径 + 相对路径"。
- 所有网络调用带超时（AbortSignal/timeout）；统一错误格式 `[委托失败] <原因>`；支持 `--dry-run`（打印请求体时**密钥脱敏**）。
- 密钥只从本地凭据文件/环境变量读取，绝不硬编码。

## 阶段 1：图片识别

1. OpenAI 兼容：`POST {baseURL}/chat/completions`，content 数组同时放 `{type:'text'}` 与 `{type:'image_url', image_url:{url: DataURL}}`。
2. 验证：先纯色探测确认能看图，再请用户发一张真实图片，识别并描述；确认正确后该能力标记"已接入"。

## 阶段 2：图片生成

1. OpenAI 兼容：`POST {baseURL}/images/generations`，参数 `model / prompt / n / size(1K|2K|3K|4K) / ratio`。
2. 图生图、多图合成：传 `extra_body.image`（数组，URL 或 Data URL，本地文件自动转换）。
3. **关键坑**：请求 `response_format: b64_json` 必须放 **extra_body 内**，放顶层无效。
4. 返回兼容：可能返回 `b64_json` 或 `url`，两种都处理。
5. 验证：生成一张图 → 识别模型反向描述 → 对比与提示词是否吻合 → 展示 → 用户确认。

### 提示词撰写规范（官方文档结构，显著提升质量）

- **文生图**：`[主体] + [场景/环境] + [风格] + [光照] + [构图] + [质量要求]`
- **图生图**：`[改变要求] + [新风格/场景] + [添加或移除的元素] + [需要保留的元素]`（明确写"保留原始构图/布局"）
- **多图合成**：说明每张参考图的角色与组合方式（如"第一张为主角，第二张为产品参考"）
- **高信息密度图**：明确视觉层次（主主体/背景/次要细节）+ 风格 + 光照 + 构图约束
- 尺寸知识：非原生尺寸会被标准化映射（如 1920x1080 → 1K/16:9 的 1312x736）；需要特定分辨率时优先用模型原生尺寸档位（1K/2K/3K/4K），必要时生成后本地裁剪。

## 阶段 3：视频识别

1. 同 chat 接口，内容块类型为 `video_url`（本地视频转 Data URL）；`--max-tokens` 给足（8000+），复杂多步分析加 `thinking:true`（若模型支持）。
2. 限制：本地视频 >80MB 时 Base64 内联可能超出模型输入限制，先压缩再传（可复用展示规范中的转码工具）。
3. 验证：完成一次多步分析（"描述画面 + 逐字列出所有文字 + 分析人物动作和镜头变化"），确认正确。

## 阶段 4：视频生成（任务式三步走）

1. **提交**：`POST {baseURL}/videos`：`model / prompt / num_frames / frame_rate / width / height / seed / negative_prompt`；图生视频传 `image`（URL 或 Data URL）；关键帧动画传 `extra_body.image + extra_body.mode:"keyframes"`。
2. **帧数硬规则**：`num_frames` 有上限（如 ≤441）且常要求满足 **8n+1**（81/121/241/441 帧），时长 = 帧数 ÷ fps，推荐 24fps——以模型文档为准。
3. **轮询**：`GET {baseURL}/videos/{task_id}`；404 时退回文档推荐的备选查询接口（如 `{baseURL}/agnesapi?video_id=<ID>`）；10 秒间隔，10 分钟超时；status 为 completed/failed/error 才停止。
4. **下载**：优先任务返回的 `url`/`metadata.url`，其次按文档给出的存储桶拼接规则（如 `{outputBaseURL}/videos/{model}/{task_id}.mp4`）。
5. **限流与队列**：约 2 次/分钟；503 队列满（含 `queue_full` 字样）或 429 时退避重试（20/40 秒，最多 20 次）。
6. **端点铁律**：供应商有多个域名时，必须选**带文件存储桶的那个**（历史教训：某 `.cn` 端点生成"成功"但文件不上传，下载不到）。不确定时先各提交一单小任务实测下载，再固化。
7. 下载失败必须如实报告任务 id 与下载地址，请用户协助，不得谎称已获得文件。

### 提示词撰写规范

- **文生视频**：`[主体] + [动作] + [场景] + [镜头运动] + [光线] + [风格]`
- **图生视频**：描述哪些内容应运动、哪些关键元素保持稳定（如"面部和服装保持完全一致"）
- **关键帧动画**：描述帧间过渡关系与一致性要求
- 需要排除的内容用 `--negative`（反向提示词）；固定 `--seed` 可复现结果。

## 阶段 7：规范固化与交付

1. 把**模型配置表（能力 → 支持状态 → 模型 → 接口格式）**、提示词结构、展示规范、踩坑清单整理成协议，写入该环境可持久化的位置（全局配置/记忆文件/项目说明文件，如 `AGENTS.md`、`CLAUDE.md` 等，取决于平台），注明"对后续所有会话生效"。更换模型时只需更新配置表，协议主体不变。
2. **API Key 不写入协议与任何文档**：协议与 README 只记录配置表（模型名、接口格式、baseURL），密钥单独存本地凭据文件，脚本统一从凭据文件/环境变量读取。
3. 编写冒烟脚本：一键检查 ① 各能力配置在位（凭据文件可读）② 客户端补丁在位 ③ 工具链文件齐全，并允许对每个能力单独跑最小实测。
4. 编写 README：全部用法、参数说明、模型配置说明、踩坑清单、密钥安全说明。
5. **自愈演练**：手动删掉/覆盖补丁，验证自检脚本能自动恢复。
